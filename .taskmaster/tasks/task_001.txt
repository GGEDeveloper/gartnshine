# Task ID: 1
# Title: Implement Mobile Camera Capture Component
# Status: pending
# Dependencies: None
# Priority: high
# Description: Enable mobile admin users to capture product photos directly via device camera in product forms.
# Details:
Create `/public/js/camera-capture.js` using HTML5 getUserMedia API for camera access. Integrate Canvas API for preview and manipulation. Add camera capture UI to `/views/admin/products/form.ejs` and style with `/public/css/admin-camera.css`. Ensure fallback to file input for unsupported devices.

# Test Strategy:
Test on Chrome, Safari, Firefox mobile. Validate camera permission prompt, preview overlay, capture functionality, and fallback on desktop.

# Subtasks:
## 1. Create Camera Access Module [pending]
### Dependencies: None
### Description: Implement the core camera access logic using the HTML5 getUserMedia API in `/public/js/camera-capture.js` to request camera permissions and initialize the video stream.
### Details:
Write a JavaScript module that checks for camera support, requests user permission, and initializes the camera stream. Handle permission denied and unsupported browser scenarios. Use feature detection to determine if getUserMedia is available.

## 2. Implement Camera Preview UI [pending]
### Dependencies: None
### Description: Add a live camera preview overlay to the product form using the Canvas API, allowing users to see what the camera captures in real time.
### Details:
Extend `/public/js/camera-capture.js` to render the camera stream onto a `<canvas>` element. Position the preview overlay appropriately within `/views/admin/products/form.ejs`. Ensure the preview mirrors the device orientation and fills the designated area.

## 3. Add Capture Button and Event Handling [pending]
### Dependencies: None
### Description: Integrate a capture button into the UI that, when pressed, freezes the current preview and prepares the image for upload.
### Details:
Add a capture button to the form. On click, capture the current canvas frame as an image (e.g., using `canvas.toDataURL()`). Store the captured image temporarily for preview and upload. Provide visual feedback (e.g., flash effect) on capture.

## 4. Implement File Upload Fallback [pending]
### Dependencies: None
### Description: Provide a fallback file input for devices or browsers that do not support camera access, ensuring the form remains functional everywhere.
### Details:
Dynamically show/hide the camera UI and a traditional file input based on feature detection. Ensure the file input is styled consistently and integrates with the existing multer upload system.

## 5. Style Camera Capture UI [pending]
### Dependencies: None
### Description: Apply custom styles to the camera preview, capture button, and fallback file input to ensure a cohesive admin interface.
### Details:
Create `/public/css/admin-camera.css` with styles for the camera preview, capture button, and file input. Ensure the UI is responsive and matches the admin theme. Handle transitions between camera and file input modes gracefully.

## 6. Integrate with Multer Upload System [pending]
### Dependencies: None
### Description: Connect the captured image or selected file to the existing server-side multer upload pipeline, ensuring seamless integration with the product form submission.
### Details:
Modify the form submission handler to accept either a camera-captured image (as a data URL or Blob) or a traditional file. Convert the camera image to a file object if necessary. Ensure the upload endpoint processes both sources correctly.

## 7. Handle Permissions and Errors [pending]
### Dependencies: None
### Description: Implement robust error handling for camera access, permissions, and upload failures, with user-friendly feedback.
### Details:
Add error handling for camera initialization, permission denial, and upload errors. Display clear messages to the user and provide recovery options (e.g., retry, switch to file input). Log errors for debugging.

## 8. Cross-Browser and Device Testing [pending]
### Dependencies: None
### Description: Conduct comprehensive testing across target browsers and devices to ensure consistent behavior, performance, and fallback functionality.
### Details:
Test on iOS Safari, Chrome Android, Firefox mobile, and desktop browsers. Validate camera access, preview, capture, upload, and fallback in each environment. Check for memory leaks and performance issues.
