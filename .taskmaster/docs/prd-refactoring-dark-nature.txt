# PRD - Gonzaga Art & Shine: Refactoring Dark Nature Theme

## Contexto do Projeto
Sistema Node.js + Express + EJS + MySQL existente em produção para joalharia alternativa.
Branch de trabalho: feature/planning-fase1-fase2
Ambiente: WSL em Windows 11, deploy em cPanel/Dominios.pt

## Objetivo da Refatoração
Aplicar identidade visual "Gothic Natural" ao sistema existente SEM MIGRAÇÃO de plataforma, mantendo toda a funcionalidade atual e adicionando:
- Tema Dark Nature completo (Ónix + Olho-de-tigre)
- Filtros funcionais por pedra natural e metal
- Storytelling "Origem da Matéria" nas páginas de produto
- Base preparada para sistema multi-vendedor (futuro)
- Performance otimizada para hosting partilhado

## Especificações Visuais APROVADAS

### Identidade
- Conceito: Gothic Natural - elegância que nasce da terra
- Slogan: "Elegância que nasce da terra"
- Tipografia: Títulos em Cinzel (600), corpo em Source Sans 3 (400/600)
- Pedras prioritárias: Ónix (negro profundo) e Olho-de-tigre (dourado)
- Metais UI: Prata e dourado equilibrados (50/50)
- SEM azulejos portugueses, SEM selo "Gonzaga Approved"

### Alterações Base de Dados
Adicionar campos à tabela `produtos`:
- stone_type ENUM('onix', 'olho-de-tigre', 'outros')
- stone_origin VARCHAR(120) - origem geográfica
- metal_finish ENUM('prata_925', 'prata_com_ouro', 'outros')
- metal_purity VARCHAR(50) - ex: 925, 18k
- artisan_name VARCHAR(100) - nome do artesão
- crafting_technique VARCHAR(150) - técnica de fabricação
- care_instructions TEXT - instruções de cuidado

Criar índices para performance:
- idx_produtos_stone_type
- idx_produtos_metal_finish
- idx_produtos_stone_metal (composto)

### Controllers e Rotas
- controllers/catalogoController.js (novo - filtros, ordenação, paginação)
- controllers/baseController.js (dados comuns para todas as views)
- Atualizar routes/site.js com novas rotas:
  * GET / - home-dark
  * GET /catalogo?pedra=&metal=&ordenar= - catálogo filtrado
  * GET /produto/:slug - PDP com storytelling
  * GET /vendedores - página artesãos
  * GET /manifesto - origem e cuidados

### Assets Necessários
- Texturas de background (ardósia, madeira negra, botânica escura)

## Funcionalidades Principais

### 1. Filtros de Catálogo
- Por tipo de pedra (Ónix, Olho-de-tigre, Todas)
- Por acabamento metal (Prata 925, Prata com ouro, Todos)
- Ordenação (Mais recentes, Preço crescente/decrescente, Nome A-Z)
- Paginação (12 produtos por página)
- URL query params preservados (?pedra=onix&metal=prata_925)

### 2. Storytelling "Origem da Matéria"
Cada página de produto deve exibir:
- Pedra natural: nome científico + origem geográfica
- Metal: tipo + pureza
- Artesão: nome (se disponível)
- Técnica de fabricação
- Instruções específicas de cuidado por tipo de pedra/metal

### 3. Performance e SEO
- Lazy loading nativo em imagens (loading="lazy")
- Compressão gzip/brotli para CSS/JS
- Cache headers para assets estáticos (7d CSS, 30d imagens)
- Meta tags SEO em todas as páginas
- Open Graph para redes sociais
- Preload de fontes críticas (Cinzel, Source Sans 3)

### 4. Responsividade
- Mobile-first approach
- Breakpoints: 720px (tablet), 1024px (desktop)
- Grid responsivo: 4 cols desktop → 3 tablet → 2 mobile
- Menu mobile (toggle button visually-hidden por padrão)
- Hero com background-attachment: scroll no mobile (fix iOS)

### 5. Acessibilidade
- Contrastes AA em todos os textos
- Reduce motion para prefers-reduced-motion
- Labels semânticos em formulários
- Alt text descritivo em imagens
- Print styles (ocultar nav/footer/botões)

## Riscos e Mitigações

### Risco 1: Performance em hosting partilhado
Mitigação: Otimização agressiva, cache headers, lazy loading

### Risco 2: Compatibilidade com sistema existente
Mitigação: Testar em ambiente local idêntico antes de deploy

### Risco 3: Fontes Google Fonts causando FOUT
Mitigação: Usar font-display: swap + preload

### Risco 4: Imagens grandes causando LCP alto
Mitigação: Lazy loading + WebP + compressão
