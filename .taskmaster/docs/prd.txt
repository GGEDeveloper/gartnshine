# PRD: Mobile Camera & Media Management Enhancement
## Gonzaga's Art & Shine - Sistema de Catálogo Online

---

## 📋 VISÃO GERAL

### Contexto
Sistema web existente para catálogo de joalharia em prata 925 com inspiração Bali/Boho. Stack: Node.js + Express + MariaDB + EJS templates. Atualmente funcional com gestão de produtos, stock e catálogo público.

### Objetivo
Adicionar funcionalidades mobile-first de captura de imagens e gestão avançada de media para otimizar o workflow do administrador e melhorar a experiência visual do catálogo.

### Scope
- **INCLUÍDO:** Mobile camera integration, media management avançado, image optimization
- **EXCLUÍDO:** E-commerce completo, analytics avançado, AI features

---

## 🎯 PROBLEMAS A RESOLVER

### Problema 1: Workflow Ineficiente de Adicionar Produtos
**Situação Atual:** Admin está na loja física → vê produto novo → tira foto no telemóvel → transfere para computador → faz upload no admin → adiciona produto.

**Impacto:** Demora muito tempo, produtos não são adicionados rapidamente, oportunidades de venda perdidas.

**Solução Desejada:** Admin tira foto diretamente no admin mobile → produto criado imediatamente com foto otimizada.

### Problema 2: Imagens Pesadas Afetam Performance
**Situação Atual:** Uploads diretos de fotos de telemóvel (3-5MB cada), sem otimização, carregamento lento em shared hosting.

**Impacto:** Site lento, experiência ruim, custos de bandwidth, limites de storage atingidos.

**Solução Desejada:** Compressão automática, múltiplas variantes (thumbnail/medium/large), formato WebP com fallback.

### Problema 3: Gestão de Media Difícil
**Situação Atual:** Pasta /media com imagens, sem organização, difícil encontrar/reutilizar imagens, não sabe quais estão em uso.

**Impacto:** Uploads duplicados, storage desperdiçado, dificuldade em manter organização.

**Solução Desejada:** Interface visual drag & drop, tracking de uso, media library reutilizável, smart organization.

## 🚀 FUNCIONALIDADES REQUERIDAS

## SPRINT 1: Mobile Camera Admin (PRIORIDADE MÁXIMA)

### Feature 1.1: Mobile Camera Capture
**Descrição:** Botão "Tirar Foto" nos formulários de produto (criar/editar) que ativa a câmara do dispositivo.

**Requisitos Técnicos:**
- HTML5 getUserMedia API para acesso à câmara
- Canvas API para preview e manipulação
- Fallback para input file tradicional em desktop
- Compatibilidade: Chrome/Safari/Firefox mobile

**Acceptance Criteria:**
- [ ] Botão "Tirar Foto" visível apenas em dispositivos mobile
- [ ] Ao clicar, solicita permissão de câmara ao utilizador
- [ ] Stream de vídeo aparece em preview overlay
- [ ] Botão "Capturar" tira a foto e fecha o overlay
- [ ] Foto aparece como preview no formulário
- [ ] Possível retomar foto se não gostar
- [ ] Fallback para upload tradicional funciona

**Implementação Sugerida:**
- Criar `/public/js/camera-capture.js`
- Adicionar componente em `/views/admin/products/form.ejs`
- CSS específico em `/public/css/admin-camera.css`

### Feature 1.2: Multi-Camera Switch
**Descrição:** Alternar entre câmara frontal e traseira do dispositivo.

**Requisitos Técnicos:**
- MediaDevices.enumerateDevices() para listar câmaras
- Constraints switching entre facingMode: 'user' e 'environment'
- UI toggle button no camera overlay

**Acceptance Criteria:**
- [ ] Botão toggle câmara visível durante captura
- [ ] Alterna suavemente entre câmaras sem crash
- [ ] Mantém settings (zoom, etc) ao alternar se possível
- [ ] Default para câmara traseira (melhor qualidade)

### Feature 1.3: Real-time Image Compression
**Descrição:** Comprimir imagem client-side antes de enviar ao servidor.

**Requisitos Técnicos:**
- Canvas API para resize
- toBlob() com quality parameter
- Target: reduzir 3-5MB para ~500KB
- Manter aspect ratio original

**Acceptance Criteria:**
- [ ] Imagem capturada é automaticamente comprimida
- [ ] Target size: máx 800px na maior dimensão
- [ ] Quality: 85% JPEG
- [ ] Preview mostra imagem já comprimida
- [ ] Indicador visual de "Comprimindo..." durante processo
- [ ] Upload mais rápido que sem compressão

### Feature 1.4: Quick Product Creation Workflow
**Descrição:** Formulário simplificado para criar produto rapidamente com foto.

**Requisitos Técnicos:**
- Nova rota `/admin/products/quick-add`
- Campos obrigatórios mínimos: foto + nome + preço
- Auto-gerar referência se vazio
- Redirect para edição completa após criar

**Acceptance Criteria:**
- [ ] Formulário quick-add com apenas 4 campos: foto, nome, preço venda, família
- [ ] Validação mínima (apenas obrigatórios)
- [ ] Produto criado com status "active" por default
- [ ] Após salvar, redirect para edição completa com mensagem "Adicione mais detalhes"
- [ ] Acessível via botão destacado no admin mobile

## SPRINT 2: Advanced Media Management (ALTA PRIORIDADE)

### Feature 2.1: Drag & Drop Gallery Interface
**Descrição:** Interface visual moderna para gerir a pasta /media com drag & drop.

**Requisitos Técnicos:**
- HTML5 Drag & Drop API
- Grid layout responsivo
- Thumbnail generation via Canvas
- AJAX upload sem page reload

**Acceptance Criteria:**
- [ ] Página `/admin/media-gallery` criada
- [ ] Grid de thumbnails mostra todas as imagens de /media
- [ ] Drag & drop de ficheiros para área designada funciona
- [ ] Upload progress bar visível
- [ ] Múltiplas imagens podem ser arrastadas de uma vez
- [ ] Preview imediato após upload bem-sucedido
- [ ] Mensagem de erro clara se upload falhar

### Feature 2.2: Automatic Image Variants
**Descrição:** Criar automaticamente 3 versões de cada imagem: thumbnail (200px), medium (800px), large (1600px).

**Requisitos Técnicos:**
- Server-side: Sharp library (se viável) ou Canvas API
- Client-side fallback: Canvas API
- Naming convention: filename_thumb.jpg, filename_medium.jpg, filename_large.jpg
- Storage: mesmo diretório da original

**Acceptance Criteria:**
- [ ] Ao fazer upload, 3 versões são criadas automaticamente
- [ ] Thumbnail: 200x200px (crop square)
- [ ] Medium: 800px maior lado, aspect ratio mantido
- [ ] Large: 1600px maior lado, aspect ratio mantido
- [ ] Original também é mantida
- [ ] Processo é invisível ao user (automático)
- [ ] Se falhar, ainda salva a original

### Feature 2.3: WebP Format Conversion
**Descrição:** Converter automaticamente imagens para WebP com fallback para JPEG/PNG.

**Requisitos Técnicos:**
- Canvas toBlob() com type 'image/webp'
- Criar versão .webp de cada variante
- HTML <picture> element com fallback
- Browser feature detection

**Acceptance Criteria:**
- [ ] Para cada imagem, versão .webp é criada
- [ ] Templates EJS usam <picture> com source webp + fallback
- [ ] WebP usado em browsers que suportam
- [ ] JPEG/PNG usado automaticamente em browsers antigos
- [ ] File size reduzido em ~30-50% vs JPEG
- [ ] Qualidade visual mantida

### Feature 2.4: Media Library Modal
**Descrição:** Pop-up modal para selecionar imagens existentes em vez de fazer novo upload.

**Requisitos Técnicos:**
- Modal overlay com grid de imagens
- Filtro/search por nome
- Single/multiple selection mode
- Integration com product forms

**Acceptance Criteria:**
- [ ] Botão "Escolher da Biblioteca" em product forms
- [ ] Modal abre com todas as imagens da media library
- [ ] Grid responsivo com thumbnails
- [ ] Search box filtra por nome do ficheiro
- [ ] Click seleciona imagem e fecha modal
- [ ] Imagem selecionada aparece no form
- [ ] Possível selecionar múltiplas imagens (checkboxes)

### Feature 2.5: Media Usage Tracking
**Descrição:** Sistema para saber onde cada imagem é usada no site.

**Requisitos Técnicos:**
- Nova tabela: media_usage (id, image_filename, used_in_table, used_in_id)
- Trigger ao associar imagem a produto
- Query para listar usos de uma imagem
- UI warning ao tentar deletar imagem em uso

**Acceptance Criteria:**
- [ ] Database tracking de onde imagens são usadas
- [ ] Ao deletar imagem, warning se está em uso
- [ ] Lista "Usado em: Produto X, Galeria Y"
- [ ] Badge "Em uso" vs "Não usado" nos thumbnails
- [ ] Filter "Mostrar apenas não usadas" para cleanup
- [ ] Safe delete: só permite se não estiver em uso

## 🔧 TECHNICAL REQUIREMENTS

### Stack Constraints
- **Manter:** Node.js + Express + MariaDB + EJS
- **Adicionar:** Sharp (optional, server-side image processing)
- **Browser APIs:** getUserMedia, Canvas, Drag&Drop, IntersectionObserver
- **No frameworks pesados:** Vanilla JS ou bibliotecas leves

### Performance Targets
- **Image upload:** < 2 segundos para foto comprimida
- **Camera activation:** < 500ms
- **Gallery load:** < 1 segundo para 50 thumbnails
- **Compression ratio:** 80-90% size reduction
- **WebP savings:** 30-50% vs JPEG

### Compatibility Requirements
- **Mobile:** iOS Safari 14+, Chrome Android 90+
- **Desktop:** Chrome 90+, Firefox 88+, Safari 14+
- **Graceful degradation:** Fallback para upload tradicional
- **Progressive enhancement:** Funcionalidades avançadas se disponíveis

### Security Requirements
- **File validation:** Apenas imagens (JPEG, PNG, WebP, GIF)
- **File size limit:** Máx 10MB antes compressão
- **Sanitize filenames:** Remove caracteres especiais
- **CSRF protection:** Manter tokens existentes
- **Permission checks:** Admin only para media management

### Database Changes
```sql
-- Nova tabela para tracking de media
CREATE TABLE media_files (
    id INT PRIMARY KEY AUTO_INCREMENT,
    filename VARCHAR(255) UNIQUE NOT NULL,
    original_filename VARCHAR(255),
    file_size INT,
    mime_type VARCHAR(100),
    width INT,
    height INT,
    has_thumbnail BOOLEAN DEFAULT 0,
    has_medium BOOLEAN DEFAULT 0,
    has_large BOOLEAN DEFAULT 0,
    has_webp BOOLEAN DEFAULT 0,
    uploaded_by INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (uploaded_by) REFERENCES users(id)
);

CREATE TABLE media_usage (
    id INT PRIMARY KEY AUTO_INCREMENT,
    media_id INT NOT NULL,
    used_in_table VARCHAR(100) NOT NULL,
    used_in_id INT NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (media_id) REFERENCES media_files(id) ON DELETE CASCADE,
    INDEX idx_media_id (media_id),
    INDEX idx_usage (used_in_table, used_in_id)
);
```

## 🚧 CONSTRAINTS & DEPENDENCIES

### Technical Constraints
- **Shared hosting:** Recursos limitados (CPU, RAM, storage)
- **No Node.js modules pesados:** Evitar Sharp se possível, usar Canvas API
- **Backward compatibility:** Não quebrar funcionalidades existentes
- **Mobile-first:** Mas desktop também deve funcionar

### Dependencies
- Multer já instalado (file uploads)
- Express session já configurado
- Middleware de auth já existe
- Sistema de notificações já implementado

### Risks & Mitigations
| Risco | Impacto | Probabilidade | Mitigação |
|-------|---------|---------------|-----------|
| Browser não suporta getUserMedia | Alto | Baixa | Fallback para upload tradicional |
| Sharp não funciona em shared hosting | Médio | Média | Client-side Canvas fallback |
| Storage limits atingidos | Alto | Média | Cleanup de imagens não usadas, compression |
| Performance issues com muitas imagens | Médio | Média | Pagination, lazy loading, thumbnails |
